## Design clarifications to review

- Workflow-directory workspace; current-directory `.repro` lookup for status/resume.
- Strict ASCII relative file paths, portable alias checks, and limited basename globs.
- Private input copies, reserved Python executable resolution, and runner-only output publication.
- Content keys include script bytes, direct dependency output hashes, and an explicit conservative environment record; installed wheels can have a null source-lock digest.
- Filesystem/cache/SQLite publication is ordered, not jointly atomic; completed work needs current verification before readiness.
- Resume inherits cache mode, preserves history, and can retain verified outputs with cache disabled.
- Ordinary cancellation owns live child groups; abrupt-death orphan work and arbitrary external side effects have explicit limits.

See [decisions](design-decisions.md) and the [acceptance matrix](design.md#n-verification-and-measurement-plan). No material design blocker has been identified. P02 smoke tests ran; application behavior tests and benchmarks have not run.

- `CacheStorage` stores one complete `metadata.json` plus declared artifacts under `.repro/cache/v1/<key>/`, validates the complete entry on every lookup, quarantines invalid final entries, and distinguishes operational cache failures. ## P06 state and recovery

- Schema version 1 in `.repro/state.sqlite3` records logical runs, numbered invocations, task selections, numbered attempts, complete artifact inventories, and per-invocation resolutions. All state changes use short explicit SQLite transactions with rollback journaling, full synchronization, foreign keys, and a bounded busy timeout. Successful attempt and artifact insertion commit together before dependent readiness. A stable run ID survives resume, and prior attempts/logs remain untouched.
- `runner status RUN_ID` reads a consistent stored view from the current workspace without requiring the workflow file or changing application state. `runner resume RUN_ID` checks the normalized original contract, inherits cache mode and last worker count unless overridden, and reevaluates declared inputs, direct producer outputs, environment identity, and the full published outputs. It retains valid committed work, otherwise restores from verified cache when enabled or executes a new attempt. Explicit resume also handles prior failed and completed runs. A P05-era attempt directory without database state cannot be inferred or resumed.
- On-disk and separate-process tests cover state opening, unsupported schema, transaction rollback, artifact atomicity, history, status, successful and failed work, equivalent and changed workflows, script/data/glob/environment changes, producer output behavior, corrupt cache repair, no-cache independence, ownership, and storage errors. Synchronized SIGKILL tests pause at launch intent, child activity, cache publication, multi-output restoration, pre/post SQLite success, no-cache publication, and an actual in-flight SQLite transaction with a hot rollback journal. SIGINT and SIGKILL recovery and a confirmed old-attempt late write use bounded fixture processes. Known fixture children were cleaned up; no broad process discovery or cleanup of unrelated orphans was attempted.
- The full local suite passed 214 tests with no failures or skips. Ruff lint and format checks passed. Six installed-CLI demonstrations in disposable workspaces observed: stored status with key/input/output/log evidence and unknown-run exit 2; SIGINT after two commits, followed by one retained result, one cache restoration and two new executions with hashes equal to an uninterrupted reference; SIGKILL on a no-cache run, followed by one retained and two new executions, then a missing-output reevaluation with no cache directory; cache-published-before-SQLite-success recovery from a new cached attempt versus no-cache reexecution; contract and concurrent-owner rejection without new invocation records; and a real old child writing `b:late` to its private attempt after resume while the published and cache artifact hashes stayed unchanged. The controlled crash tests also checked the actual journal rollback and that precommit attempts were not rewritten as successes.
- These checks are macOS local evidence. Multi-file publication and SQLite are not one atomic operation; a gap between launch intent and confirmed OS launch has an unknown historical launch count. Trusted command side effects are not exactly once. Linux behavior, clean wheel/source-distribution installation, hosted CI, JSON manifests, seeded simulation, benchmark evidence, and remote publication remain later gates.
